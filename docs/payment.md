# 支付系统

在 acg-faka 原有的支付插件机制上，新增 4 个支付插件和 1 个公共工具目录，商品下单和余额充值都能用。

| 插件目录 | 后台名称 | 对接对象 | 支付方式（code） |
|---|---|---|---|
| `app/Pay/Yipay` | 易支付 | 彩虹易支付协议（MD5），以及兼容该协议的平台 | `alipay` 支付宝、`wxpay` 微信、`qqpay` QQ钱包、`bank` 云闪付 |
| `app/Pay/AlipayOpen` | 支付宝官方 | 支付宝开放平台，RSA2 公钥模式 | `face` 当面付扫码、`page` 电脑网站、`wap` 手机网站、`web` 按设备自动选 |
| `app/Pay/WechatPayV3` | 微信支付官方 | 微信支付 APIv3 直连商户 | `native` 扫码、`h5` 手机浏览器 H5 |
| `app/Pay/UsdtGateway` | 收U（USDT/USDC） | 自建的 BEpusdt / epusdt / GM Pay 网关 | `usdt.trc20`、`usdt.bep20`、`usdt.polygon`、`usdt.arbitrum`、`usdt.ton` 等，`cashier` 由用户在网关收银台自选 |
| `app/Pay/PayKit` | （不是插件） | 公共代码：参数签名、RSA、HTTPS 请求、本站扫码收银台 | — |

实现时参考的项目：
- 支付宝、微信支付的官方文档与 SDK，以及 yansongda/pay
- 独角数卡（assimon/dujiaoka）的易支付对接代码，彩虹易支付原版源码（查单接口）
- BEpusdt、GM Pay（assimon/epusdt）的源码与 API 文档：签名算法、回调格式和重发规则都按最新版源码核对过

## 在后台启用

1. **支付管理 → 支付插件**：在对应插件上点「配置」，填写商户参数。同一个插件可以「新增」多套配置，比如两个商户号。
2. **支付管理 → 支付接口**：点「新增」，依次选择：
   - 支付插件
   - 支付方式（即上表里的 code）
   - 使用哪套配置
   - 是否用于「商品购买」和「余额充值」
   - 显示名称和图标（`/assets/user/images/cash/` 下有 `alipay.png`、`wechat.png`、`usdt.png`）
3. 用一个小额商品实际付一笔，确认能收到回调并自动发货。

**回调地址**由系统自动生成，格式为 `<域名>/user/api/order/callback.<订单号>`，充值是 `/user/api/rechargeNotification/callback.<订单号>`，不用在支付平台后台另外填写。如果站点挂了 CDN，或者支付平台访问不到买家用的那个域名，就在后台基础设置里填「回调域名」。回调地址必须能从公网访问。

## 各插件的参数从哪里来

### 易支付
- **网关地址**：易支付平台的接口根地址，例如 `https://pay.example.com/`。误填成带 `submit.php` 的地址也能识别。
- **商户ID / 商户密钥**：平台分配的 pid 和 MD5 key。
- **下单方式**：
  - 「跳转收银台」用 `submit.php`，兼容性最好。
  - 「接口下单」用 `mapi.php`，拿到二维码后在本站收银台展示。

### 支付宝官方
- 先在开放平台创建应用，签约要用的产品：当面付 / 电脑网站支付 / 手机网站支付。
- **APPID**：应用的 APPID。
- **应用私钥**：用支付宝密钥工具生成。PEM 格式或单行 base64 都可以。
- **支付宝公钥**：在「接口加签方式」里，把应用公钥上传后，页面显示的那个支付宝公钥。注意不是应用公钥。
- **网关地址**：正式环境留空即可。沙箱填 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`。
- 只支持**公钥模式**，不支持公钥证书模式。

### 微信支付官方（APIv3）
- **商户号 / AppID**：AppID 必须已经在商户平台和该商户号完成关联。
- **APIv3 密钥**：商户平台 → API 安全，32 位。
- **商户证书序列号、商户 API 私钥**：申请 API 证书后得到。私钥就是 `apiclient_key.pem` 的内容。
- **微信支付公钥 + 公钥ID**：商户平台 → API 安全 → 微信支付公钥。老商户也可以填平台证书的内容和它的序列号。
- 需要在商户平台开通 Native 支付或 H5 支付。H5 支付还要登记 H5 支付域名。

### 收U（USDT/USDC）

自己部署一套开源的 USDT 收款网关，本插件负责对接。网关直接监听区块链，不经过任何交易所，所以**没有地区限制，也不需要交易所 API Key**；支持的链也最多。

- **部署网关**：推荐 [BEpusdt](https://github.com/v03413/BEpusdt)（专为个人收款设计），也可以用 [GM Pay](https://github.com/assimon/epusdt)（原 epusdt）。在网关后台添加你的收款钱包地址（可以是自己的钱包，也可以是交易所的充值地址）。
- **网关类型**：BEpusdt 和经典 epusdt 选「MD5 签名」；GM Pay 新版选「HMAC-SHA256」，并填 PID。
- **网关地址**：网关的根地址，也可以直接填完整的 `create-transaction` 接口地址。
- **API Token**：
  - BEpusdt：后台 → 系统管理 → API 设置 → 对接令牌。
  - GM Pay：API Key 的 secret_key。
- **汇率**：一般留空，用网关自己的汇率设置；填了就强制使用，写法同网关（`7.2`、`~1.02`、`+0.05`）。
- **付款页面**：默认「本站收银台」——网关下单时已经返回收款地址和应付币数，直接在本站展示金额、地址二维码、倒计时，以及按网络生成的「转账说明和提醒」（如「仅可通过 BSC (BEP20) 发送 USDT，请勿发送 BNB 或其他资产」、提现手续费要另加、出问题时提供订单号和交易哈希），底部保留网关收银台链接备用。选「收银台自选」或用 GM Pay 时，先展示说明，再由买家点按钮去网关收银台选网络。也可以改成「直接跳转网关收银台」。
- 网关后台添加钱包时，**交易类型要和本站支付方式一致**：本站开的是 `usdt.bep20`，网关里就要有 `usdt.bep20` 类型的钱包。注意 `ethereum.eth` 是收以太坊 ETH 本身，不是 USDT。币安等交易所的 0x 充值地址通常在 BSC、以太坊、Arbitrum、Polygon 上通用，同一个地址可以按不同交易类型各加一条（以币安 App 里该网络显示的地址为准）。
- 支付方式 code 直接作为 BEpusdt 的 `trade_type` 传过去，表示指定收款链；`cashier` 表示让用户在网关收银台自己选。GM Pay 一律由收银台选择。
- 回调里的 `amount` 是人民币金额，会和订单金额逐分核对。
- **回调重发**：BEpusdt 判断回调是否送达只看 HTTP 状态码。插件验签失败时会返回 HTTP 500，网关按 2、4、8…分钟退避重发，最多 10 次；在网关后台能看到失败记录，方便发现 Token 填错。BEpusdt 每分钟推送的「等待支付」和到期时的「已超时」通知，插件验签后直接忽略，不会写失败日志。
- 网关没有按商户单号查单的接口，所以收U不支持主动查单，靠网关自己重发通知。网关要能访问本站的回调地址。

## 主动查单（通知丢失时兜底）

正常情况下，本站靠支付平台的异步通知确认收款。如果通知一直没到，比如服务器宕机、回调被防火墙拦了、平台重试次数用完，订单就会停在「未付款」。主动查单就是这时由本站去平台查这笔单，确认已付款后照常发货或入账。

**支持的插件**：易支付、支付宝官方、微信支付官方。收U不支持，原因见「收U」一节。

**两个触发入口：**
- **买家停在本站收银台时**：扫码页、H5 中转页每轮询三次就让本站去平台查一次单，大约 18 秒一次。买家付完款，即使通知没到，页面也会在半分钟左右变成「支付成功」。
- **定时任务** `app/Pay/PayKit/cron.php`：覆盖买家已经离开页面的情况，以及跳转收银台、表单提交这类不经过本站收银台的支付方式。它会找出最近 24 小时内未付款、且用的是支持查单插件的商品订单和充值单，逐笔查单。单越老查得越慢：10 分钟内的单每分钟查一次，之后间隔约为订单年龄的 1/10，最长 30 分钟一次。

定时任务要每分钟跑一次：

```bash
# Docker：在宿主机的 crontab 里加一行
* * * * * docker exec faka-local php /var/www/html/app/Pay/PayKit/cron.php >/dev/null 2>&1

# 宝塔等非 Docker 环境：计划任务 → Shell 脚本，--site 填站点地址
php /www/wwwroot/你的站点/app/Pay/PayKit/cron.php --site=https://你的域名
```

手动跑一次可以看到每笔单的查询结果，方便排查。

**怎么保证查单结果可信：**
- 查单请求复用支付回调地址（`/user/api/order/callback.<单号>`，带 `pay_query=1`）。插件不按通知验签，而是去平台查单。平台确认已付款后，查到的结果交给系统，后面的单号核对、金额逐分核对、重复通知拦截、串行化事务、发货全部走系统原有流程。查单只是换了一种方式拿到付款结果，不会绕过任何核对。
- 支付宝、微信的查单应答都要验签，签名对不上就不认。易支付的查单接口不带签名，可信度靠 HTTPS 和只有你知道的商户密钥，所以**易支付网关地址务必用 https**。
- 这个地址谁都能请求，所以只查本插件的、未付款的、24 小时内创建的订单，同一笔单 10 秒内最多查一次。
- 平台说已付款但金额对不上时，系统拒绝发货，原因写在该支付插件目录的 `runtime.log` 里。

如果在后台开了「支付回调白名单 IP」，买家浏览器发起的查单会被挡掉，定时任务也要把本机 IP 加进白名单。

## 安全设计

- **调网关接口时校验 TLS 证书。** acg-faka 自带的 `Base::http()` 关闭了证书校验，这里没有用它。
- **支付宝当面付和微信下单都会校验网关应答的签名**，防止返回的二维码或支付链接被中间人替换。
- **回调验签之外还要核对商户身份**：易支付核对 pid，支付宝核对 app_id，微信核对 mchid 和 appid，GM Pay 核对 pid。别的商户号发来的通知一律不认。
- **金额核对、重复通知、并发锁这三项由系统核心负责**，在插件验签之后执行：金额必须和订单逐分一致；已支付的订单再收到通知直接拒绝；处理回调用的是串行化事务。
- **微信、收U回调验签失败时返回 HTTP 500。** 系统默认拒绝回调时返回 200，而微信 APIv3 和 BEpusdt 只要收到 200 就不再重发，配置有误时这笔款就再也收不到通知了。
- **微信回调解密后，只保留需要的字段写回系统**；支付宝的 `TRADE_FINISHED` 状态统一视为支付成功。

## 测试

`tests/pay/MockGateway.php` 是一个支付网关模拟器，`tests/pay/e2e.php` 是端到端测试。模拟器里的签名和加密是独立实现的，不调用插件代码，所以测试能真正交叉验证插件实现对不对。

每种支付方式都会走两遍完整流程：
- **商品下单**：真实下单 → 买家看到的支付页（跳转、表单提交或本站收银台）→ 网关验签 → 异步回调 → 订单变为已付款并自动发货。
- **余额充值**：建一个临时会员并签发登录会话 → 充值 ¥12.34 → 同样走支付页和回调 → 充值单已付款、余额到账、账单记一笔「充值」。

两遍都会核对网关实际收到的金额和异步通知地址。另外还覆盖这些异常情况：
- 篡改签名的通知
- 签名正确但金额不符的通知
- 重复通知（充值时核对不会重复入账）
- 微信、收U验签失败时返回 500
- BEpusdt 的「等待支付」状态推送：回 200、订单不变、不写失败日志（模拟器按最新版 BEpusdt 的格式发回调，`actual_amount` 为字符串）
- 支付宝应答验签失败
- 充值带接口手续费：网关收的是面额加手续费，余额只到账面额
- 串单重放：把 A 充值单签名正确的通知投到金额相同的 B 单回调地址，必须被拒绝
- 主动查单：易支付、支付宝、微信的每种支付方式，商品订单和充值单都测。模拟器只把单标成已付款、不发通知，查单后必须发货或入账；还没付款、已付款、10 秒内重复查、金额不符、支付宝查单应答验签失败、超过 24 小时这几种情况都不能发货，也不能重复入账。定时任务 `cron.php` 也会实际跑一遍。

在 Docker 容器里运行：

```bash
docker cp tests faka-local:/tmp/acg-tests
docker exec faka-local php /tmp/acg-tests/pay/e2e.php              # 跑完自动清理测试数据
docker exec faka-local php /tmp/acg-tests/pay/e2e.php --item=10    # 换一个带小数价格的商品
docker exec faka-local php /tmp/acg-tests/pay/e2e.php --keep       # 保留测试订单，方便到后台查看
docker exec faka-local php /tmp/acg-tests/pay/e2e.php --cleanup    # 清理 --keep 留下的数据
```

测试期间会临时关闭下单验证码，结束后自动恢复。测试数据靠这几样识别：名称以 `E2E ` 开头的支付接口和配置、联系方式为 `e2e-test` 的订单、会员名为 `e2e_recharge` 的临时会员。清理时只删这些，不会碰站点自己的数据。

## Docker 部署注意

官方镜像把 `app/Pay` 软链到数据卷 `/data/pay`，只有容器**第一次启动**时会从镜像里拷贝一份。所以已经在跑的站点要手动把新插件拷进数据卷：

```bash
docker cp app/Pay/. <容器名>:/data/pay/
docker exec <容器名> chown -R www-data:www-data /data/pay
```

## 暂不支持

- 支付宝公钥证书模式
- 微信 JSAPI / 小程序支付（需要获取用户 openid）
- 退款接口
- 易支付 V2（RSA）协议
- 不经过网关、由本站直接监听钱包地址的链上转账（请用 BEpusdt / GM Pay 网关）

以上功能都只用模拟网关测过，还没有和真实的支付宝、微信、易支付平台、BEpusdt 联调。上线前请用真实账号做一笔小额实付验证。
