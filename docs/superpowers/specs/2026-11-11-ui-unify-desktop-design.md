# 界面统一与电脑布局设计（子项目 B）

日期：2026-11-11。状态：设计已在对话中逐段批准（含同日的方向调整），本文待用户审阅。

本文是「界面改版」项目的第 2 个子项目，整体拆分见文末「所属项目」。原定的 B 是「后台外壳与概览，删除旧皮肤」。用户 2026-11-11 反馈两个问题：用户端在电脑上只是一条窄栏；用户端和后台风格完全不一样。B 因此改为：皮肤同时管前后台、后台和代理商后台换侧栏外壳、用户端加电脑布局。总览页的内容不在本次范围内。

**用户 2026-11-11 的决定**：
1. 保留 11 套皮肤，再把用户端现在的深青样子加成第 12 套「深青自助」。在「外观与品牌」里选哪套，用户端、后台、代理商后台、登录页一起换。（先定的是「删掉皮肤、后台改用用户端这套」，同日改为现在这样。）
2. 去掉「主色」设置，配色全听皮肤的。
3. 从没保存过皮肤的站点，默认皮肤由「曜夜雾金」改为「深青自助」。
4. 用户端电脑布局：左边操作、右边帮助的两栏，加上横跨两栏的步骤条（对比图里的 A 加 B）。
5. 后台外壳：深色侧栏（对比图 B），侧栏底色从当前皮肤的主色推出。
6. 后台这一轮只换外壳，各页面里的内容和排版不动，总览页内容也不动。

**写规格时按代码事实做的调整**（对话里批准的设计之外，请审阅时重点看）：
1. 步骤条沿用兑换页现有的 3 步打勾进度（核对卡密 → 核对账号 → 开通），不是对比图里画的 5 步。对话里已说明。
2. 用户端的按钮是纯色，用皮肤的主色和按钮字色，不用皮肤的渐变、阴影这类按钮装饰（曜夜雾金暗色下的金色渐变按钮，在用户端也是纯金色）。大字大按钮的好认是改版 A 的核心，装饰会降低对比度。
3. 「实际是不是暗色」由两件事决定：用户选了暗色（或跟随系统时系统是暗色），或者皮肤本身就是暗色（赛博科技、熔岩霓光、粗野主义）。用户端的提醒、出错、禁用这几种颜色按「实际是不是暗色」取亮或暗的一套。根元素上加一个标记 `data-tone="dark|light"` 表示它；`html.dark` 类照旧只表示用户选的模式，Element Plus 的暗色仍靠它。
4. 侧栏选中项除了主色底，还加粗、加一条左边白色竖线。按规则核对颜色时发现，主色和侧栏底色的对比度只有 1.08–2.35，只靠底色分不出选中的是哪一项（§3.4）。
5. 电脑布局下，页面里原有的「返回首页」链接不显示，因为导航条上已经有「兑换」；窄屏照旧显示（§4.2）。
6. 侧栏顶部去掉现在固定的菱形图标，有 Logo 显示 Logo，没有就只显示站名（§5.1）。
7. 注册页 `/auth/register` 也算登录类页面，和后台登录、首次设置、代理商登录一起换。
8. 批量兑换、查账单、卡密查询、代理换码这四页的说明文字都是紧挨着输入框的提示，挪开就看不懂了，所以留在原位；这四页的右栏放常见问题（§4.5）。
9. 导航条上的「批量兑换」「账单查询」「常见问题」沿用页脚现有的文字，只新增「兑换」一个词（英文 Redeem）。

## 1. 目标

1. 买家用电脑打开时，看到的是正经的宽屏页面，不是拉长的手机页。
2. 管理员和买家看到的是同一个产品：选了哪套皮肤，前后台的配色、圆角、背景都是那套。
3. 用户端不管用哪套皮肤，字都看得清、按钮都认得出。

做成的标准：
- 宽 1440、1024 的电脑屏幕上，用户端每页都是两栏，没有大片空白，没有横向滚动条。
- 手机宽 390 时，用户端布局和改版前一样（颜色随皮肤变）。
- 12 套皮肤、亮暗两种，用户端的文字和按钮对比度都不低于 4.5:1（§3.3）。
- 换一套皮肤，用户端、后台、代理商后台、登录页一起变。

## 3. 皮肤与配色

### 3.1 新皮肤「深青自助」

- 皮肤编号 `teal`，名称「深青自助」，英文 Teal Kiosk。排在皮肤列表第一位。
- 颜色用改版 A 的配色表（A 规格 §3.1）：

| 皮肤变量 | 亮色 | 暗色 |
|---|---|---|
| `--bg` | #EEF5F3 | #0C1A18 |
| `--surface`、`--surface-solid` | #FFFFFF | #132522 |
| `--surface-2` | #E2EDEC | #1C423C |
| `--brd` | #DCE5E3 | #22403B |
| `--brd-2` | #C9D8D5 | #2C524B |
| `--ink` | #0E2A26 | #E6F1EE |
| `--ink-2`、`--ink-3` | #4A6560 | #9DB5B0 |
| `--primary` | #0F6B5F | #3FB8A5 |
| `--primary-hover` | #13806F | #5CC7B6 |
| `--primary-active` | #0B5249 | #2FA08F |
| `--primary-soft` | #E2EDEC | #1C423C |
| `--primary-on` | #FFFFFF | #0C1A18 |
| `--bg-tint` | none | none |

- 圆角：`--radius-sm` 8px、`--radius-md` 14px、`--radius-lg` 14px。
- 字体：系统字体（§3.5），不加载 Google 字体。标题用无衬线。
- 不是默认暗色的皮肤。

### 3.2 用户端从皮肤取颜色

用户端的变量改为指向皮肤变量，不再自己定颜色：

| 用户端变量 | 取自 |
|---|---|
| `--u-bg` | `--bg` |
| `--u-surface` | `--surface-solid`（不透明，玻璃质感皮肤的卡片和输入框也看得清） |
| `--u-ink` | `--ink` |
| `--u-muted` | `--ink-2` |
| `--u-line` | `--brd` |
| `--u-primary` | `--primary` |
| `--u-on-primary` | `--primary-on` |
| `--u-tint` | `--primary-soft` |
| `--u-warn-*`、`--u-error-*`、`--u-disabled-*` | 不随皮肤变，用改版 A 的值；按 `data-tone` 取亮或暗的一套（文首调整 3） |

- 用户端的页面底色不再自己画，透出 `html` 上皮肤的底色和背景装饰（如曜夜雾金的柔光、赛博科技的网格）。
- 圆角：按钮和输入框用皮肤的 `--radius-md`，卡片用 `--radius-lg`。高度、字号、边框粗细照旧（A 规格 §3.3）。
- 按钮是纯色：底色 `--u-primary`、字色 `--u-on-primary`（文首调整 2）。

### 3.3 对比度

用户端要求以下几对颜色的对比度不低于 4.5:1。12 套皮肤，每套按亮色、暗色两种各算一遍（默认暗色的三套皮肤只算它自己那一种）：

| 文字 | 底色 | 用在哪 |
|---|---|---|
| `--ink` | `--bg`、`--surface-solid` | 正文、标题 |
| `--ink-2` | `--bg`、`--surface-solid` | 次要文字 |
| `--primary-on` | `--primary` | 按钮上的字 |
| `--primary` | `--surface-solid` | 链接、空心按钮的字、输入框边 |

不达标的，调那套皮肤的颜色：优先把 `--primary` 往深（亮色）或往浅（暗色）调，`--ink-2` 同理；色相不变。调过的值同时写进皮肤的 Element Plus 主色，后台跟着变。写规格时只核对了亮色的「按钮字在主色上」这一对，已知不达标：薄荷清新 3.77、曜夜雾金 3.85（赤陶奶油 4.53、玫瑰杂志 4.70 刚过线）。其余几对和暗色的完整清单由 §9.2 的测试列出。

### 3.4 侧栏颜色

侧栏用的四个颜色由当前皮肤在当前模式下的主色推出（和 Element Plus 按钮用的是同一个主色），不另存设置。推导方法和现有的 `darkPrimaryFrom` 一样用 HSL：

| 名称 | 规则 |
|---|---|
| side-bg | 保持主色的色相和饱和度，亮度每次降 0.02，直到白字在它上面的对比度不低于 10:1 |
| side-ink | 普通菜单文字：白色占 78%、side-bg 占 22% 混合 |
| side-muted | 分组标题：白色占 60%、side-bg 占 40% 混合 |
| side-active | 选中的菜单项底色用主色，字用皮肤的按钮字色（`primaryOn`） |

深青自助亮色（主色 #0F6B5F）的结果：side-bg #0A473F（白字 10.57）、side-ink #C9D7D5（7.13）、side-muted #9DB5B2（4.88）。写规格时按这套规则核对过 6 个色相不同的主色和 3 个边界颜色（刚好满足 4.5:1 的最浅灰 #767676、接近黑的 #05080A、石墨 #36454F）：白字在 side-bg 上 10.04–20.08，side-ink 6.80–12.10，side-muted 4.63–7.30，都达标。

**选中项不能只靠底色区分**：主色和 side-bg 的对比度只有 1.08–2.35。所以选中项同时有三样：主色底、字体加粗、左边一条 3px 白色竖线（白色在 side-bg 上不低于 10:1，满足非文字元素 3:1 的要求）。

### 3.5 字体

- **用户端**：一律用系统字体 `-apple-system, "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`，不跟皮肤的字体，也不加载 Google 字体（国内访问 Google 字体很慢甚至打不开）。卡密、邮箱、数字用 `"SF Mono", "JetBrains Mono", Menlo, Consolas, monospace`。
- **后台、代理商后台、登录类页面**：照旧用皮肤的字体，Google 字体照旧只在后台页面按需加载。登录类页面和代理商后台不加载（沿用现在只在 `/ops` 下加载的规则），显示系统字体。

### 3.6 亮暗模式

- 优先级不变：本机的选择（`localStorage` 键 `theme-mode`）> 后台 `theme_mode` 设置 > 跟随系统。
- `html.dark` 只表示上面这个选择的结果，Element Plus 的暗色靠它，和现在一样。
- 新增 `html[data-tone]`：`dark` 表示「实际是暗色」（`html.dark`，或皮肤本身是暗色），否则 `light`（文首调整 3）。
- `index.html` 里首屏前的小脚本照旧提前设置皮肤和暗色，默认皮肤改为 `teal`，并同样写上 `data-tone`。

## 4. 用户端电脑布局

### 4.1 什么时候用

- 窗口宽度不小于 1024px：电脑布局。
- 小于 1024px（手机、平板竖屏）：现在的单栏，结构、尺寸、间距都不变。

### 4.2 顶部导航条

- 整宽一条，`--u-surface` 底，下边一条 `--u-line` 色分隔线。
- 左：Logo（有就显示）和站名，点了回首页。
- 中：「兑换」`/`、「批量兑换」`/batch`、「账单查询」`/billing`、「常见问题」（首页里跳到 `#help`，其他页去 `/#help`）。当前页的链接用主色加粗，并带 `aria-current="page"`。
- 右：语言切换、亮暗切换（现有组件）。
- 窄屏（小于 1024px）：只留 Logo、站名、语言、亮暗，和现在一样；其他链接仍在页脚。
- 页面里原有的「返回首页」链接在电脑布局下不显示，窄屏照旧显示。

### 4.3 两栏

- 内容区最宽 1120px，居中，左右至少 24px 留白。
- 标题和说明在两栏上方，左对齐。
- 左栏约 3/5 放操作，右栏约 2/5 放帮助，栏间距 32px。两栏顶端对齐，右栏不吸顶。
- 宽表格（卡密查询的批量结果）出现时，放在两栏下方，占满内容区整宽。

### 4.4 步骤条

- 用兑换页现有的 3 步打勾进度（`ProgressTicks`：核对卡密 → 核对账号 → 开通）。
- 电脑布局下横跨两栏，放在标题下面、两栏上面。
- 首页在电脑布局下也显示，第 1 步是当前步。窄屏的首页照旧不显示，兑换页照旧显示。
- 批量兑换、账单查询、卡密查询、代理换码不显示步骤条。

### 4.5 每页右栏放什么

| 页面 | 左栏 | 右栏 |
|---|---|---|
| 首页 `/` | 粘贴卡密、卡密状态或「卡密在哪」 | 常见问题（现有 7 条） |
| 兑换：核对卡密 | 同首页 | 常见问题 |
| 兑换：粘贴登录信息 | 粘贴框、点数须知、按钮 | 「怎么拿登录信息」的分设备说明（`DeviceGuide`） |
| 兑换：核对账号、开通中、结果 | 当前这一屏的内容 | 常见问题 |
| 批量兑换、账单查询、卡密查询、代理换码 | 现在页面上的全部内容，输入框旁的提示留在原位 | 常见问题 |

- 窄屏时右栏内容回到原来的位置：首页的常见问题在下方，`DeviceGuide` 在粘贴框上方，其他页不显示右栏，和现在一样。
- 常见问题只有一份组件，各页右栏共用。
- 页面上 `id="help"` 只出现一次。

### 4.6 不变的东西

文案、按钮、流程、接口、带码链接（`?cdk=`、`?code=`）、刷新恢复都不变。只改位置。

## 7. 前端结构

## 8. 出错时怎么处理

- Logo 加载失败：只显示站名，不显示破图。
- 读站点设置失败：用默认站名和本机记住的皮肤（没有就用 `teal`），页面照常可用。
- `localStorage` 读写失败（无痕模式等）：皮肤和亮暗按站点设置。
- 本机记住的皮肤编号不在列表里（比如以后删了某套）：用 `teal`。

### 9.2 前端（vitest）

- **对比度**：测试读 `style.css`，按皮肤和亮暗算出每套皮肤实际生效的变量（先取 `:root`，再叠皮肤亮色块，暗色再叠暗色块；默认暗色的皮肤只算它自己那一种），对 §3.3 表里每一对断言不低于 4.5:1。失败信息写出皮肤、模式、哪一对、实际值。

## 10. 上线

### 10.1 发版说明要写的

按「升级注意」三块写在最前面：

**升级前必须做：**
- 想让用户端保持现在的深青样子、又在后台选过别的皮肤的：升级后马上到「系统 → 外观与品牌」把皮肤改成「深青自助」并保存。升级后用户端会立刻换成后台选的那套皮肤。

**升级后要确认：**
- 刷新所有开着的后台页面。
- 到「系统 → 外观与品牌」确认皮肤是想要的那套。从没保存过皮肤的站点，前后台都会变成「深青自助」（后台原来默认是曜夜雾金）。
- 用电脑打开首页，确认是左右两栏，上面有步骤条。

**行为变化：**
- 皮肤改为同时管用户端和后台，新增「深青自助」并设为默认。
- 「外观与品牌」去掉主色设置，按钮颜色由皮肤决定；以前设的主色不再起作用。
- 为了让用户端的字和按钮看得清，几套皮肤的颜色调深或调浅了一点，后台也跟着变（具体哪几套见更新说明）。
- 后台和代理商后台换成深色侧栏；代理商后台原来是顶部导航。
- 用户端在电脑上（宽度不小于 1024px）改为两栏，顶部有导航条；手机上布局不变。
- 公开站点接口 `GET /api/v1/public/site` 不再返回 `primary_color`，`skin` 默认值改为 `teal`。

### 10.2 真实环境验证

升级后用户用电脑打开首页和后台看一眼，再在「外观与品牌」换一套皮肤，看用户端是否跟着变。Claude 去线上看时，两次之间至少间隔 10 分钟。
